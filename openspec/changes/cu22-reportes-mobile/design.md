# Diseño

`mobile_telemedicina/lib/features/analytics/reportes/` contiene modelos, repositorio, controlador y pantalla CU22. `analytics/exportacion/` contiene la descarga CU27 y reutiliza `ReportQuery`. La ruta existente `/analytics` apunta a la pantalla de reportes con guard de sesión. Home ofrece la entrada solo cuando `/auth/me` ya fue verificado, el perfil declara ADMIN activo con `id_clinica` y el backend autoriza `GET /analytics/reportes/catalogo`; esta última comprobación cubre estado de rol y clínica que `/auth/me` no expone.

El controlador mantiene un borrador, la respuesta normalizada y una generación monotónica. Cambiar definición o cuenta invalida respuestas anteriores; la exportación solo acepta la definición normalizada vigente. La paginación usa la misma definición y modifica solo `pagina`. El cliente HTTP común añade Bearer; `id_clinica` nunca entra en el cuerpo. Un 403 retira los datos y el acceso de analytics sin cerrar la sesión. Un 401 de analytics retira primero ese acceso; solo se cierra la sesión si `/auth/me` también devuelve 401. La comprobación adicional del catálogo no bloquea la navegación tras un login o `/auth/me` exitoso. Un token de «recordarme» desactivado permanece solo en memoria durante la sesión y no provoca una salida al volver a comprobarla en el mismo proceso.

El proyecto no tenía guardado de archivos binarios. Se usa `file_saver` 0.4.x, cuyo requisito de Dart coincide con el SDK declarado, para ofrecer selector de guardado en Android/iOS y descarga del navegador en web. Se reciben bytes autenticados, se valida MIME y nombre antes de invocar el guardado. En web la ubicación final la decide el navegador; en Android/iOS la decide el usuario en el diálogo. Se usa `--dart-define=API_BASE_URL=...` para la prueba aislada sin editar la URL de producción existente. La resolución real de dependencias y la compatibilidad final del plugin quedan pendientes de `flutter pub get` y build en otro equipo.

No hay tablas, migraciones ni cambio de contrato.
